# Touchstone v1.0.0 Plan

Status: complete, 2026-11-05. Released as 1.0.0 (commit a2991d4 and the release commits that follow it). Archived to archive/V1.0_PLAN.md.

This plan takes Touchstone from 0.3.0-alpha straight to 1.0.0 in one release. There are no intermediate alpha, beta, or published release candidate builds. Release candidates are validated from a local package feed only (see Workstream 13).

1.0.0 is a compatibility promise. After it ships, breaking changes to the public API, the JSON results schema, the console exit codes, or the telemetry names require 2.0.0. Every breaking change Touchstone needs therefore lands in this release, and the tooling in Workstream 10 stops new ones from slipping in afterward.

Authorization: under VERSIONING.md, the version bump to 1.0.0 (Workstream 14, step 3) and every publish step need explicit user approval at the time they run. Approving this plan does not cover them.

## 1. Confirmed decisions

| Topic | Decision |
|---|---|
| xUnit | Support both v2 and v3 through two renamed packages: `Touchstone.Xunit2Adapter` and `Touchstone.Xunit3Adapter`. `Touchstone.XunitAdapter` is deprecated on nuget.org, with `Touchstone.Xunit2Adapter` as the alternative. The `Touchstone` metapackage drops all framework adapters and contains only Core and Cli. |
| Skips | The default is native skip with the reason: xUnit v3 skip, NUnit ignore, MSTest inconclusive. xUnit v2 has no runtime skip, so it falls back to a pass with the skip reason written to test output; this limitation is documented. Users can change the behavior through `TestRunOptions` and adapter options. |
| Mutability | Results and descriptors are immutable. Descriptors provide `With*` copy methods. Execution delegates cannot be replaced, whether the case is a scenario or an ordinary case. |
| Cancellation | `RunAsync` stops and returns a canceled summary. The in-flight case finishes or cancels, after-suite cleanup runs, the remaining cases are `NotRun`, and the summary is marked canceled. Throwing entry points throw `OperationCanceledException`. Ordinary cases and scenarios follow the same rules. |
| Parameter order | `CancellationToken` is always the last parameter of every public async method. |
| Options | A `TestRunOptions` object configures every engine entry point. |
| Interfaces | Extension points can grow after 1.0 without breaking implementers (Workstream 3). |
| Filtering | Tag-based filtering in Core, the console runner, and every adapter. |
| Duplicate IDs | Duplicates are rejected before execution, with an unambiguous ID grammar. |
| Hardening | Public API tracking, a versioned JSON schema, a telemetry freeze, a release pipeline, a style and XML doc cleanup, consumer validation, and documentation. |

## 2. Decisions made in this plan (open to veto)

These follow from the confirmed decisions or from the code review. Each one is a breaking change, or would become expensive after 1.0. Strike any you disagree with before implementation starts.

1. **`TestOutcome` replaces `Success` and `Skipped`.** Today `TestResult.Success` is documented as "True when the test passed or was skipped". With canceled and not-run outcomes added, two booleans can no longer describe a result. The new enum is `Passed`, `Failed`, `Skipped`, `Canceled`, `NotRun`.
2. **Skip state is a single `SkipReason`.** The `skip` bool plus `skipReason` pair allows contradictory states (skipped with no reason, or a reason on a case that isn't skipped). A non-null `SkipReason` means the case is skipped, and a blank reason is rejected.
3. **`TestCaseDescriptor.ExecuteAsync` is no longer public.** All execution goes through `TestExecutor` or an adapter. Calling the delegate directly bypasses skips, telemetry, cancellation classification, and scenario handling, so exposing it invites misuse. This also removes the special case where only scenario delegates are read-only.
4. **Suite hook failures become results.** Today a `BeforeSuiteAsync` exception aborts the whole run. Under the new rules, it marks that suite's cases `Failed` with the hook exception (matching NUnit's `OneTimeSetUp` behavior), still runs `AfterSuiteAsync`, records a `SuiteLifecycleError`, and continues with the next suite. An `AfterSuiteAsync` failure records a `SuiteLifecycleError`. Either failure makes the run unsuccessful. This matches the cancellation decision: outcomes are reported in the summary, not thrown. Exceptions thrown by a sink still abort the run, because a broken reporter is an infrastructure failure.
5. **One canceled-case rule.** A case is `Canceled` when it throws `OperationCanceledException` while the caller's token has cancellation requested. Today scenarios also require `ex.CancellationToken == token`, which misclassifies linked-token cancellations (for example from `HttpClient`) as failures. An `OperationCanceledException` thrown while the caller's token is not canceled is `Failed`.
6. **Hook and cleanup budget.** When the caller cancels, `AfterSuiteAsync` receives a fresh token limited by `TestRunOptions.CleanupTimeout` (default 30 seconds, the same range as `ScenarioBuilder.CleanupTimeout`). It does not receive the already-canceled caller token.
7. **Consistent adapter shapes.** Each adapter exposes the same three parts, named `Touchstone{Framework}Cases` (data source), `Touchstone{Framework}` (static execute helper), and `Touchstone{Framework}FactBase` (run-all base class). The xUnit packages are being renamed anyway, so 1.0 is the time to make the names consistent.
8. **Serializable row keys.** Theory and data rows carry a serializable case key (the `TestId`) rather than the descriptor, and resolve it back to the descriptor at execution time. Test Explorer then shows one row per case under xUnit v2 and v3. Duplicate IDs (decision 10) are what make this resolution safe.
9. **Tags map to native traits.** Tags become xUnit traits, NUnit categories, and MSTest categories where the framework allows per-row metadata. Native filters (`dotnet test --filter`) then work alongside Touchstone's own filter.
10. **ID grammar.** `SuiteId` allows `[A-Za-z0-9_-]` and `CaseId` allows `[A-Za-z0-9_.-]`, and neither may be blank. Today `TestId` is `SuiteId + "." + CaseId`, which is ambiguous: suite `A.B` with case `C` produces the same ID as suite `A` with case `B.C`. Banning `.` in suite IDs makes every `TestId` parse uniquely. Tags allow `[A-Za-z0-9_.:-]` and are compared case-insensitively.
11. **The JSON root becomes an object with `schemaVersion`.** This is the last cheap chance to replace the bare array, and the step `durationMs` (double) vs result `durationMs` (long) mismatch is fixed at the same time.
12. **The JSON DTOs become internal.** `JsonResultEntry` and `JsonStepEntry` are serialization details. The published JSON Schema becomes the contract.
13. **Telemetry span names become low-cardinality.** `suite:{id}`, `case:{id}`, `stage:{name}`, and the other prefixed names move to fixed names (`touchstone.suite`, `touchstone.case`, and so on), with the IDs kept as attributes. This follows TELEMETRY_REQUIREMENTS.md and OpenTelemetry guidance, and it breaks dashboards that match on the old names. That's acceptable only in this release.
14. **AOT support for Core and Cli.** REPOSITORY_REQUIREMENTS.md item 15 requires an AOT decision and, where the library is capable, a `Test.Aot` project. Core is close to AOT-safe already. Cli needs source-generated JSON. The adapters are out of AOT scope, because the test frameworks rely on reflection.
15. **Console exit codes.** `0` means every selected case passed (or was skipped under `Report`), `1` means a failure or lifecycle error, `2` means canceled, and `3` means invalid arguments. These become part of the 1.0 contract.

## 4. Target package layout

| Package | Depends on | Notes |
|---|---|---|
| `Touchstone.Core` | BCL only | AOT-compatible. |
| `Touchstone.Cli` | Core | AOT-compatible, with source-generated JSON. |
| `Touchstone.Xunit2Adapter` | Core, `xunit.extensibility.core` 2.9.x | Replaces `Touchstone.XunitAdapter`. Namespace `Touchstone.Xunit2Adapter`. |
| `Touchstone.Xunit3Adapter` | Core, `xunit.v3.extensibility.core` 4.0.2+ | New. Namespace `Touchstone.Xunit3Adapter`. Works with either test runner (Microsoft Testing Platform or VSTest), because the consumer chooses the runner package. |
| `Touchstone.NunitAdapter` | Core, NUnit 5.0+ | |
| `Touchstone.MstestAdapter` | Core, MSTest.TestFramework 4.4+ | |
| `Touchstone` | Core, Cli | Metapackage. The adapters are removed because bundling xUnit v2, xUnit v3, NUnit, and MSTest forces conflicting dependencies on consumers. |

Adapter packages reference the framework's extensibility or core package, never the framework's test-project metapackage. Referencing the metapackage would turn the consumer's library into a test project, which is the same class of bug that 0.2.0 fixed. Phase 0 confirms the exact package IDs.

`Touchstone.XunitAdapter` stays on nuget.org at 0.3.0-alpha and is marked deprecated, with `Touchstone.Xunit2Adapter` named as the alternative. This is a manual nuget.org action by the package owner.

## 5. Target public API

The shipped API is recorded in each package's `PublicAPI.Unshipped.txt` and is authoritative. Where it differs from these sketches, the progress log in section 12 says why (for example `ConsoleRunner.RunMainAsync`, `JsonReport` and `HtmlReport`, `TestRunAssert`, `ITestSuiteProvider`, and the MSTest row keys).

These are sketches. Names and members are final unless implementation turns up a concrete problem, which gets recorded here before the plan is changed. All types follow the repository style: block namespaces, sorted usings inside the namespace, `_PascalCase` private fields, full XML documentation, and guarded inputs.

### 5.1 Mutability rule

- **Model types are immutable:** `TestCaseDescriptor`, `TestSuiteDescriptor`, `TestResult`, `TestRunSummary`, `ScenarioStepResult`, `ScenarioMetadata`, `SuiteLifecycleError`. Each has a public constructor that validates and copies its inputs (so tests of custom sinks can build them), get-only properties, and defensively copied collections.
- **Configuration types are mutable:** `TestRunOptions`, `TestFilter`, `ConsoleRunnerOptions`. They have validating setters, and the engine snapshots them when a run starts, so changing an options object during a run has no effect.
- **Builders are mutable and not thread-safe:** `ScenarioBuilder<TContext>`.
- A reflection-based contract test enforces the first rule (Workstream 8).

### 5.2 Core types

```csharp
public enum TestOutcome { Passed, Failed, Skipped, Canceled, NotRun }

public enum SkipBehavior
{
    Report, // default: skipped result; adapters use the native skip
    Omit,   // skipped cases are not executed, reported, or counted (like filtered cases)
    Fail    // skipped cases become Failed with SkippedCaseNotAllowedException
}

public sealed class TestCaseDescriptor
{
    public TestCaseDescriptor(string suiteId, string caseId, string displayName,
        Func<CancellationToken, Task> executeAsync,
        IReadOnlyList<string>? tags = null, string? skipReason = null);

    public string SuiteId { get; }
    public string CaseId { get; }
    public string TestId { get; }              // SuiteId + "." + CaseId, unambiguous by grammar
    public string DisplayName { get; }
    public IReadOnlyList<string> Tags { get; } // copied, validated, never null
    public string? SkipReason { get; }         // null when not skipped
    public bool IsSkipped { get; }
    public ScenarioMetadata? Metadata { get; }

    public TestCaseDescriptor WithTags(IReadOnlyList<string> tags);
    public TestCaseDescriptor WithSkip(string reason);
    public TestCaseDescriptor WithoutSkip();
    public TestCaseDescriptor WithDisplayName(string displayName);
    // With* preserves any attached scenario definition.
}

public sealed class TestSuiteDescriptor
{
    public TestSuiteDescriptor(string suiteId, string displayName,
        IReadOnlyList<TestCaseDescriptor> cases,
        Func<CancellationToken, ValueTask>? beforeSuiteAsync = null,
        Func<CancellationToken, ValueTask>? afterSuiteAsync = null);
    // Throws DuplicateTestIdException on a duplicate CaseId, and ArgumentException when a
    // case's SuiteId does not match the suite.
    // Get-only SuiteId, DisplayName, Cases (copied), BeforeSuiteAsync, AfterSuiteAsync.
}

public sealed class TestResult
{
    public TestResult(string suiteId, string caseId, string displayName, TestOutcome outcome,
        TimeSpan duration, string? message = null, Exception? exception = null,
        IReadOnlyList<string>? tags = null, ScenarioMetadata? metadata = null,
        IReadOnlyList<ScenarioStepResult>? steps = null,
        IReadOnlyList<Exception>? cleanupExceptions = null);
    // Get-only TestId, SuiteId, CaseId, DisplayName, Outcome, Duration, Message,
    // Exception, Tags, Metadata, Steps, CleanupExceptions.
}

public sealed class TestRunSummary
{
    // Get-only Passed, Failed, Skipped, Canceled, NotRun, Total (sum of the five),
    // Filtered (selected out, not part of Total), Duration, WasCanceled,
    // LifecycleErrors (IReadOnlyList<SuiteLifecycleError>).
    // IsSuccess: Failed == 0 && Canceled == 0 && NotRun == 0 && LifecycleErrors.Count == 0.
}

public sealed class SuiteLifecycleError
{
    // Get-only SuiteId, Stage ("before_suite" or "after_suite"), Exception.
}

public sealed class TestFilter
{
    public IList<string> IncludeTags { get; }  // case matches when it has any included tag; empty means all
    public IList<string> ExcludeTags { get; }  // exclusion wins over inclusion
    public IList<string> SuiteIds { get; }     // empty means all
    public IList<string> TestIds { get; }      // empty means all
    public bool Matches(TestCaseDescriptor testCase);
}

public sealed class TestRunOptions
{
    public TestFilter Filter { get; set; }                  // default: matches everything
    public SkipBehavior SkipBehavior { get; set; }          // default: Report
    public bool StopOnFirstFailure { get; set; }            // default: false; remaining cases become NotRun
    public TimeSpan CleanupTimeout { get; set; }            // default 30 s, valid range (0, 1 day]
    // Reserved for 1.x as additive properties: CaseTimeout, MaxDegreeOfParallelism.
}
```

### 5.3 Executor

```csharp
public static class TestExecutor
{
    public static Task<TestRunSummary> RunAsync(IReadOnlyList<TestSuiteDescriptor> suites,
        ITestResultSink? sink = null, TestRunOptions? options = null,
        CancellationToken cancellationToken = default);

    public static Task<TestRunSummary> RunSuiteAsync(TestSuiteDescriptor suite,
        ITestResultSink? sink = null, TestRunOptions? options = null,
        CancellationToken cancellationToken = default);

    public static Task<TestResult> ExecuteCaseResultAsync(TestCaseDescriptor testCase,
        ITestResultSink? sink = null, TestRunOptions? options = null,
        CancellationToken cancellationToken = default);

    // Returns on Passed or Skipped. Rethrows the original exception on Failed, throws
    // OperationCanceledException on Canceled, and throws SkippedCaseNotAllowedException
    // under SkipBehavior.Fail.
    public static Task ExecuteCaseAsync(TestCaseDescriptor testCase,
        TestRunOptions? options = null, CancellationToken cancellationToken = default);
}
```

`RunAsync` validates before any execution or telemetry: it rejects null suites and duplicate `SuiteId`s across suites (`DuplicateTestIdException`). Suites with no selected cases are skipped entirely: no hooks, no sink callbacks. `ScenarioDiagnostics.ExecuteAsync` and `ScenarioHtmlReport.WriteAsync` move their `CancellationToken` to the last position. `redact` moves before the token.

### 5.4 Sink

`IScenarioStepSink` merges into `ITestResultSink`. Every member has a default no-op implementation, so new callbacks can be added in 1.x without breaking implementers:

```csharp
public interface ITestResultSink
{
    ValueTask OnRunStartedAsync(IReadOnlyList<TestSuiteDescriptor> suites, CancellationToken cancellationToken) => default;
    ValueTask OnSuiteStartedAsync(TestSuiteDescriptor suite, CancellationToken cancellationToken) => default;
    ValueTask OnCaseStartedAsync(TestCaseDescriptor testCase, CancellationToken cancellationToken) => default;
    ValueTask OnStepStartedAsync(string testId, ScenarioStepResult step, CancellationToken cancellationToken) => default;
    ValueTask OnStepCompletedAsync(string testId, ScenarioStepResult step, CancellationToken cancellationToken) => default;
    ValueTask OnCaseCompletedAsync(TestResult result, CancellationToken cancellationToken) => default;
    ValueTask OnSuiteCompletedAsync(TestSuiteDescriptor suite, TestRunSummary summary, CancellationToken cancellationToken) => default;
    ValueTask OnRunCompletedAsync(TestRunSummary summary, CancellationToken cancellationToken) => default;
}
```

- `OnTestCompletedAsync` is renamed to `OnCaseCompletedAsync` so the names pair up.
- `NotRun` results are reported through `OnCaseCompletedAsync` for the current suite. Suites after a cancellation are never started; their selected cases are counted in `NotRun`.
- Completion callbacks receive a non-canceled token, as step completion does today.
- Policy, recorded in CONTRIBUTING notes in the README: after 1.0, every new interface member must have a default implementation. A contract test fails if any `ITestResultSink` member is abstract.
- `ConsoleResultSink.WriteHeader` and `WriteOverall` become `OnRunStartedAsync` and `OnRunCompletedAsync`, and are no longer public methods.

### 5.5 Exceptions

New domain exceptions, one per file: `DuplicateTestIdException : ArgumentException`, `SkippedCaseNotAllowedException : Exception` (a specific type, not a thrown `Exception`), and `ConsoleArgumentException : ArgumentException` (Cli).

### 5.6 Adapters

The same shape for each framework:

| Part | xUnit v3 | xUnit v2 | NUnit | MSTest |
|---|---|---|---|---|
| Data source `Touchstone{Fw}Cases` | `TheoryData` of rows carrying a serializable case key, with display name, skip reason, and traits per row | `TheoryData` of an `IXunitSerializable` case key | `TestCaseData` with `SetName`, `SetCategory` per tag, and `Ignore(reason)` | `TestDataRow<T>` rows with `DisplayName`, `TestCategories`, and `IgnoreMessage` |
| Native skip (`Report`) | Row-level `Skip` at discovery; runtime skip through `DynamicSkipToken` | No runtime skip: passes, writes the reason to `ITestOutputHelper` (documented) | `Ignore` at discovery | Row-level `IgnoreMessage` at discovery (reported as Skipped) |
| `Omit` | Row not yielded | Row not yielded | Row not yielded | Row not yielded |
| `Fail` | Execution throws `SkippedCaseNotAllowedException` | Same | Same | Same |
| Helper `Touchstone{Fw}.ExecuteAsync(testCase, options, ct)` | Maps the outcome to the framework's result | Same | Same | Same |
| `Touchstone{Fw}FactBase.RunAllAsync(ct)` | Runs everything as one test; throws `AggregateException` with the original exceptions as inner exceptions | Same | Same | Same |

Base classes expose `protected abstract IReadOnlyList<TestSuiteDescriptor> Suites` and `protected virtual TestRunOptions Options`. Data sources apply `Options.Filter` and `Options.SkipBehavior` when they enumerate rows.

## 6. Workstreams

Size: S is under a day, M is one to three days, L is more than three days.

### WS1. Model immutability and outcomes (L)

- Rewrite `TestCaseDescriptor`, `TestSuiteDescriptor`, `TestResult`, `TestRunSummary`, and `ScenarioStepResult` to the shapes in 5.2. Add `TestOutcome.cs`, `SkipBehavior.cs`, `SuiteLifecycleError.cs`, `DuplicateTestIdException.cs`, and `SkippedCaseNotAllowedException.cs`.
- Apply the ID grammar and tag validation in the descriptor constructors and `ScenarioBuilder`. Add `ScenarioBuilder.WithTags` and `ScenarioBuilder.WithSkip`.
- Remove the public `ExecuteAsync` and `AttachScenario`'s self-referential delegate. The descriptor holds an internal execution body that is either a delegate or a scenario definition.
- Add `Tags` to `TestResult` so sinks and reports can group by tag.
- Update `ScenarioDefinition` to construct results through the new constructors instead of setting internal properties.

Done when the solution compiles against the new model, and the immutability and ID-grammar contract tests pass.

### WS2. Engine: options, filtering, skips, cancellation, lifecycle errors (L)

- Add `TestRunOptions.cs` and `TestFilter.cs`. Rework `TestExecutor` to the signatures in 5.3. Snapshot options at run start.
- Pre-run validation: duplicate `SuiteId`s across suites.
- Selection: apply the filter, then `SkipBehavior.Omit`; count unselected cases as `Filtered`; skip suites with no selected cases.
- Cancellation: check the token before each hook and each case. Classify with the unified rule (decision 5). Mark remaining cases `NotRun`. Run `AfterSuiteAsync` with the cleanup budget token. Set `WasCanceled`.
- Lifecycle errors: implement decision 4.
- `StopOnFirstFailure`: after the first `Failed` result, mark the remaining cases `NotRun`, still run `AfterSuiteAsync`, and leave `WasCanceled` false.
- `SkipBehavior.Fail`: produce a `Failed` result with `SkippedCaseNotAllowedException`, keeping the skip reason in the message.

Done when the new `FilterSuites`, `SkipBehaviorSuites`, `CancellationSuites`, `LifecycleSuites`, and `DuplicateIdSuites` (Workstream 8) pass under every host.

## 9. Out of scope for 1.0

These are additive later. The design leaves room for each:

- Parallel case execution (reserved: `TestRunOptions.MaxDegreeOfParallelism`).
- Per-case timeouts (reserved: `TestRunOptions.CaseTimeout`).
- Retries, reflection- or attribute-based discovery, an assertion library, and Gherkin `.feature` files.
- A recorded baseline on the dedicated benchmark runner (blocked on hardware; tracked in IMPROVEMENTS.md).
- Package signing beyond nuget.org repository signing.

2. **xUnit v3 rows:** `TheoryData<T>.Add(TheoryDataRow<T>)` with `WithTestDisplayName`, `WithSkip`, and `WithTrait` works. The native name is `"<display name>(key: <key>)"`.
3. **xUnit v3 and the .NET 10 SDK:** the `xunit.v3` package defaults to Microsoft Testing Platform, and `dotnet test` on SDK 10.0.401 fails with "Testing with VSTest target is no longer supported". `xunit.v3.mtp-off` runs under VSTest alongside the other hosts. 5. **xUnit v2:** `TheoryData<Key>` with an `IXunitSerializable` key is discovered per row. The native name is `Class.Method(key: <key.ToString()>)`, so the key's `ToString` returns the display name. There is no per-row skip or display name and no runtime skip.
6. **MSTest 4.4.1:** `IEnumerable<TestDataRow<T>>` from `[DynamicData]` supports `DisplayName` (exact native name), `TestCategories` (works with `--filter TestCategory=x`), and `IgnoreMessage` (reported Skipped). 7. **NUnit 5.0.0:** `TestCaseData.SetName`, `SetCategory`, and `Ignore(reason)` work: exact names, category filtering, and Skipped outcome.

### 2026-11-05: Steps 4 to 9, adapter suites, hosts, AOT, parity, smoke, CI, and documentation

Test architecture (WS8):
- Adapter contract suites. One shared contract (`AdapterContractSuites`, driven through `IAdapterProbe`) generates ADP-01 to ADP-24, DUP-08, TEL-12, and CAN-22 for each adapter, with the adapter code as the case-identity suffix (for example `ADP-09-X3`). - Reflection checks. The API convention checks moved to `Test.Shared.Reflection`. Reflection over metadata produced IL2026, IL2075, and IL3050 in Test.Aot, and the requirements forbid suppressing them. JIT hosts run these suites; README "AOT support" lists them as the only suites Test.Aot does not run.

New verification scripts (all write results that `scripts/verify-catalog.py` reads):
- `scripts/run-native-hosts.py`: runs every test project per framework, each with its own TRX file.
- `scripts/verify-hosts.py`: native AOT publish and run; host exit codes for help, invalid arguments, and a failing case; native JSON schema validation.
- `scripts/verify-parity.py`: `test/Parity`, a separate solution of deliberately mixed fixtures, compared across adapters and skip modes.

Found and fixed:
1. **MSTest rows were not serializable.** MSTest serializes row data at discovery. With descriptors as row data, it silently fell back to one test named "Run", which broke Test Explorer, `--list-tests`, and category filters (PAR-08 and PAR-10 caught it). MSTest rows now carry a `[DataContract]` key, `TouchstoneMstestCase`, like xUnit's. `TouchstoneMstestCases.From<TProvider>()` and `TouchstoneMstest.ExecuteAsync(key, testContext, ct)` replace the descriptor-based API.
2. **`TestContext.Current` is experimental in MSTest 4.4 (MSTESTEXP).** The MSTest helper takes the test's `TestContext` explicitly.
3. **The xUnit v2 and v3 key constructors used `[Obsolete]`, which warned anyone who called them.** They now use `[EditorBrowsable(Never)]`.
4. **The fact base classes had an undocumented implicit protected constructor (API-07 found it).** It is now documented and explicit.
5. **`TestResult` was ambiguous with `Xunit.TestResult` and MSTest's `TestResult` inside the adapters.** The adapters now fully qualify the type. An earlier error filter missed this because its file-name pattern excluded digits; the filter is fixed, and `update-public-api.py` now requires a clean compile before it reports "clean".
6. **The smoke pack clobbered the development build.** `dotnet pack -p:Version=0.0.0-smoke` rebuilt into `bin/Release`. VSTest then loaded mismatched assemblies and exited 0 without running any test or printing a summary. The pack now uses `--artifacts-path`, and `run-native-hosts.py` treats a missing summary as a failure.
7. **Solution-level `dotnet test --logger trx` file names collide** when projects finish in the same second, and the installed VSTest does not support `{assembly}` placeholders. That is why `run-native-hosts.py` exists.
8. **The sample app's `launchSettings.json` used `localhost` (SAMPLE-03).** It now uses `127.0.0.1`.
9. **The benchmark workload added one descriptor to a suite many times,** which duplicate identities now reject. It builds uniquely named cases before the timer starts.
